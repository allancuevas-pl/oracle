## Known gotchas / tech debt (don't regress)

- **Deploy aliases BOTH domains.** `vercel --prod` does NOT auto-move the custom domain `oracle.propertylions.com.au` — alias both it AND `oracle-psi-beryl.vercel.app` to the new deployment every time, then verify a deep link (`/portal`) returns 200 on the custom domain, not just `/`. (WORKFLOW.md step 4.)
- **`CLERK_JWT_ISSUER_DOMAIN` must stay set on both Convex deployments.** `auth.config.ts` references it, and Convex statically requires any referenced env var to be *set* at deploy time — the `|| fallback` does NOT satisfy the check, so `convex dev --once` / `convex deploy` fail if it's ever unset. (CLERK_PRODUCTION.md.)
- **Clerk instance swap logs everyone out once** — expected on any dev→prod cutover (old sessions carry dev tokens). Not a bug.
- **Photo extraction** (`utils/pdfPhotos.js`): per-image decode needs a mandatory ~2s timeout (pdf.js never fires the callback for undecodable images → silent infinite hang); rank candidates by JPEG byte size not pixel area; reject blank/near-white images; bounded work (≤12 photos, ≤50 images, ≤25 pages).
- **Photo/video delete orphans the storage file** — delete only drops the id from the array; the underlying Convex file remains (deliberate, avoids breaking shared refs). A cleanup pass could reclaim these later.
- **Two Convex deployments** — always deploy to both (see WORKFLOW.md). `colorless-condor-502` is the one Vercel prod actually reads.
- **Open defects from the 2026-08-27 code audit (none fixed yet).** Found by audit, not by a user — record them here so they aren't rediscovered:
  - **`extractIM` has no auth check** (`convex/imExtractionAction.ts`). Every other action guards itself via `getCurrentUser`; this one doesn't, so any signed-in user — including a `client` or `blocked` role — can invoke it and burn Anthropic credits. Needs a valid `imExtractions` id, so exposure is limited, but it's a real hole.
  - **`scripts/check-authz.js` never scans actions.** Its regex is `/export const (\w+) = (query|mutation)\(\{/` — actions sit outside the build gate entirely, which is how `extractIM` slipped through. Widen to `query|mutation|action`.
  - **`formatCurrency` is forked five ways and the copies disagree.** `CompsTab`, `PropertyAssessmentTab`, `AddCompsModal`, `ProjectFeasibilityTab` and `DetailsTab` each define a local `fmt$` using `toFixed(2)` where `src/utils/format.js` uses `toFixed(1)`. The same sale renders **$3.8M** on one screen and **$3.75M** on another; zero renders as "—" vs "$0". Violates CLAUDE.md §4. User-visible in a valuation tool.
  - **WALE goes stale when tenancies are edited.** `calcWale()` runs once at IM-scan time (`ExtractionView.jsx`) and the result is stored on `properties.wales`. `updatePropertyTenants` patches `tenants` only, and `TenancyTab` — where lease expiries are actually edited — never recomputes it. The headline figure silently keeps its scan-time value.
  - **Data quality:** `postcode` is 0% populated on all 110 comps and no property has a `state` value — which is why suggested-comps widening to "same state" can't help them, and why Will's "surrounding suburbs" search is blocked. One comp has the literal string `"Upon Completion"` in a date field.
  - **`convex/dashboard.ts` caps `matches` at `.take(500)`** with no index on status — past 500 matches the "Properties in DD" stat silently under-counts. Fine at current scale, documented so it isn't a surprise later.
- **The codebase is not bloated — don't refactor for size.** The same audit measured 18,105 lines across 90 files, zero `.collect()` calls, zero dead files, route-level code splitting, ~180 KB gzipped initial load. Large files are compositions of small co-located components. The risks here are correctness and test coverage (14 tests), not structure.
- **Deploys are manual; the live site can lag the repo.** Latest prod deploy: **`oracle-9mnp2bm1q`** (2026-09-02 — custom dropdowns + select a11y), both domains aliased and verified (`/`, `/portal`, `/comps`, `/directory` all 200; no native `select` in any live chunk).
